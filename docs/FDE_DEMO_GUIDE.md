# AI Scoring System AI 辅助评审系统 FDE 演示说明

更新日期：2026-09-07
适用版本：v1.0.2
适用场景：企业 AI 应用交付型 FDE 项目展示

## 1. 一句话说明

AI Scoring System 把“材料接入、AI 辅助分析、异常复核、人工确认和结果导出”串成一条可追踪的本机工作流。系统分别记录材料处理、模型输出、异常状态和人工决定，让使用者能够追溯结果并及时处理异常。

当前便携版使用 12 个完全虚构的案例，默认离线运行，不调用外部模型，也不包含真实学生或赛事数据。

## 2. 解决的通用业务问题

许多材料评审工作都有相似难点：文件多、格式杂，评价标准容易理解不一致，模型失败后不便续跑，异常结果需要人工确认，最终结果还要能够解释和追溯。

本系统将这些问题拆成五个连续环节：

1. 接入经过整理的证据包，并检查文件清单、哈希、路径和隐私状态。
2. 建立逐项任务状态，记录每份材料当前处于导入、校验、评分、复核还是导出阶段。
3. 通过统一 Provider 边界调用模型；切换模型时保留旧尝试，不覆盖已成功结果。
4. 将证据不足、低置信度、模型失败等情况送入人工复核队列。
5. 记录采用、调分和人工最终锁定，再判断结果是否具备正式导出条件。

这套方法可迁移到方案初审、材料完整性检查、质量评估和内容审核等场景，但需要针对新业务重新定义评分规则和验证集。当前没有其他行业客户落地证据，不把拟迁移场景表述为已实施案例。

## 3. 当前演示包含什么

### 3.1 合成案例

- 12 个固定的虚构队伍与作品案例。
- 5 段 AI 过程性评价文字，包括四个维度评语和综合评价。
- 3 份从零编写的虚构作品包，可展示代码、说明、AI 使用记录和静态预览。
- 正常完成、材料有限、必须复核、模型失败、人工采用和人工最终锁定等状态。

### 3.2 可展示的业务闭环

| 环节 | 当前可展示内容 | 验证性质 |
|---|---|---|
| 材料接入 | 合成证据包、清单和校验结果 | 离线合成数据 |
| AI 辅助结果 | 维度分、总分、评语、Flag 和答辩参考 | 预置合成结果，不是现场模型调用 |
| 异常复核 | `must_review` 阻断自动采用，复核队列展示异常原因 | 代码、测试和页面交互可验证 |
| 人工确认 | 采用既有结果、人工调整及决定记录 | 代码、测试和页面交互可验证 |
| 最终锁定 | `ManualFinalLock` 防止后续自动流程覆盖人工确认结果 | 代码和测试可验证，演示数据含锁定案例 |
| 导出准备 | 根据权威结果和阻断状态判断是否可导出 | API 和测试可验证 |

### 3.3 六个模型名称的准确含义

界面目前展示六个候选模型：千问 Qwen3.8 Max、千问 Qwen3.8 Flash、Kimi K3、智谱 GLM-5V-Turbo、豆包 Seed 2.1 Turbo、MiniMax M3。

这是一份产品侧模型选择目录，说明系统能够把模型选择作为配置传递。它不等于六条真实 Provider 通道都已配置、调用和完成效果验证。便携演示默认清空 Provider 凭据、关闭在线批量评分，初始化记录中的 `provider_calls` 为 0。

真实接入需要另行配置 Provider、凭据和能力声明，并用同一 rubric、Prompt、证据输入和结果结构做对照评测。

## 4. 5 分钟演示步骤

演示前先按照 [单机运行手册](RUNBOOK.md) 启动，并执行本机验收脚本。

### 0:00-0:40 首页：说明业务全景

打开首页，介绍系统把队伍、作品、评分、复核和导出放在同一套本机工具中。说明当前展示的是虚构数据，不需要网络模型。

### 0:40-1:30 团队管理：查看材料和 AI 评语

进入“团队管理”，选择一个已有评分的案例并打开详情。展示四个维度得分和五段过程性评语。强调评语是辅助人工理解依据，不是最终裁决。

### 1:30-2:30 评分流水线：查看逐项状态

进入“评分流水线”，查看 12 个案例的阶段和状态。指出系统会区分已完成、需要复核和失败项；失败不会被伪装成成功，也不会覆盖已有成功结果。

### 2:30-3:35 复核队列：展示必须人工介入

切换到复核队列，查看 `DEMO-P-005` 等必须复核案例。说明 `must_review` 会阻断自动采用，人员需要查看证据、模型结果和异常原因后作出决定。

### 3:35-4:25 人工锁定：展示决定权归属

查看 `DEMO-M-006` 的人工最终锁定状态。说明人工确认会形成单独记录，自动流程不能静默覆盖这一结果；需要调整时也要留下新的审计事实。

### 4:25-5:00 结果导出：说明成功条件

进入“结果导出”，展示过程性统计和结果列表。说明只有存在权威结果、没有导出阻断项时才具备导出条件；当前演示用于展示流程和控制机制，不代表真实模型准确率。

### 接口联调案例：页面能打开后继续检查控制台

历史页面检查曾发现维度请求返回 422：前端将 `current` 传给要求整数赛事 ID 的接口。当前 [TeamManage.tsx](../frontend/src/pages/TeamManage.tsx) 的 `loadCompetitionConfig` 先读取当前赛事，再使用 `res.competition.id` 获取维度；[浏览器烟测](../scripts/e2e_smoke_playwright.py) 检查页面和控制台错误。

这个案例体现 AI 辅助开发中的接口契约核对与联调验证。当前代码支持核查修正后的调用顺序；问题发现与修复过程由 AI 开发协作完成，保留需求判断与AI协作实现的职责说明。

- 页面烟测覆盖主要页面及复核队列交互，并检查浏览器控制台错误。

- Intel Mac 安装、启动、停止和本机验收均有独立脚本和说明。

### 尚未完成的效果证据

- 尚未用统一人工基准比较六个候选模型的评分误差、排序一致性和重复调用稳定性。
- 尚未证明某个模型在所有作品类型上优于其他模型。
- 离线合成结果不能用于宣称真实 Provider 准确率、成本或速度。
- 当前是单人、本机、单实例版本，不代表多用户或云端生产部署已经完成。

## 7. 小型人工基准评测方案

本节是待执行方案，本版本不调用真实模型。

### 7.1 样本与基准

- 选择 12 至 20 份经过授权和脱敏的材料，覆盖正常材料、证据不足和边界质量。模型超时、接口失败等另设故障测试，不作为材料类别。
- 两名人工评审先独立按同一 rubric 评分，再讨论较大分歧，形成可追溯的人工基准。
- 在开始模型调用前冻结样本、rubric、Prompt、输入证据和结果结构，避免边测边改口径。

### 7.2 建议比较范围

- 第一轮只选 1 个已获批准并完成能力预检的 Provider，每个样本重复调用 2 次。
- 按 12 个样本、每个重复 2 次计算，共计划 24 次调用。先检验流程可用性及与人工基准的偏差；需要回答明确的模型选型问题时，再增加第二个 Provider。
- 分别记录人工评分分歧、调用失败、材料证据不足和必须复核。仅对可评分且成功返回的结果计算误差，同时报告完整样本数、成功数和各类异常数。

### 7.3 记录指标

| 指标 | 说明 |
|---|---|
| 总分绝对误差 | 模型总分与人工基准总分的绝对差 |
| 分维度误差 | 定位误差来自哪个评分维度 |
| 排序一致性 | 比较模型排序和人工排序是否接近 |
| 重复调用稳定性 | 同一模型、同一输入两次结果的分差和评语变化 |
| 异常识别 | 证据不足或必须复核案例是否被正确送入人工复核 |
| 单份耗时 | 从请求开始到结构化结果返回的时间 |
| 单份成本 | 按 Provider 账单或 Token 记录计算，不使用估算冒充实测 |
| 人工复核耗时 | 人员检查和确认一份结果所需时间 |

评测阈值应在正式运行前由业务负责人确认。建议先把“是否能正确阻断高风险结果”作为首要门槛，再比较平均分差和成本。

## 8. 后续最小优化建议

以下建议不属于本次文档修正，实施前需要单独确认。

### 建议 1：统一模型目录的数据源

目前模型目录在前端、后端默认值和测试中分别出现，版本更新容易遗漏。建议将展示名称、能力说明和模型键集中到一份受控配置，由前后端共同读取或生成。

验收标准：修改一个模型条目后，API 与两个前端入口同步变化；不再需要手工修改多处常量；现有测试通过。

### 建议 2：明确标识“演示目录”和“已配置 Provider”

在模型选择区域区分“产品候选模型”和“当前环境可调用模型”，避免现场人员把六个名称理解为六条通道均已接通。

验收标准：离线演示明确显示“未连接在线 Provider”；只有通过能力和凭据预检的模型可以启动真实评分。

### 建议 3：增加本地基准评测命令

增加只读取脱敏评测集的本地命令，统一记录人工基准、模型输出、重复运行、耗时和成本，结果保存为不含敏感正文的评测摘要。

验收标准：固定输入可复现实验；成功结果不被覆盖；原始敏感材料不进入 Git；自动生成误差、稳定性、异常识别、耗时和成本汇总。

## 9. 展示时的推荐表述

可以说：

> 我把材料接入、AI 辅助分析、异常复核、人工确认和导出条件做成了一条可追踪工作流。这个版本用合成数据离线演示，重点证明流程控制和人机协同机制；模型效果需要用冻结的脱敏样本和人工基准单独评测。

不要说：

- 六个大模型都已经完成真实接入和效果验证。
- 合成案例可以证明真实评分准确率。
- 系统已经适用于所有行业和多用户生产环境。
- AI 可以代替人工作出最终评审决定。
