# 从作品材料到最终结果，流程是怎样设计的

我把流程拆成材料准备、AI 评分、人工复核和结果输出几部分。拆开之后，每一项材料停在哪里、需要谁处理、最终用了哪个版本，都有记录可查。

![评审流程与关键控制点](assets/review-workflow-v2.png)

蓝色是系统处理，绿色是人工决策，橙色是阻断或异常分支。图展示系统的设计；公开演示实际执行了合成评分之后的采用、锁定、结案和权威 JSON 输出，没有调用真实评分模型。

## 1. 先把材料和版本对上

同一作品可能有源代码、交互记录、截图或视频。材料没收齐、对应错了作品，后面生成的评语再流畅也没有意义。

系统用材料准备任务完成导入和校验，登记材料包、版本与校验结果。创建评分任务时，再从登记服务读取这些记录，核对来源条目、版本、输入指纹和当前校验结果。它不会只根据调用方传来的“已完成”就开始评分。

准备完成的条目还需要通过证据级别、隐私和模型输入许可等条件检查。证据“有限”和“充分”会分别保留；进入评分不代表材料质量相同。材料页让评委查看已有依据，必要时回到材料本身。

这样做是为了尽早发现输入问题。本项目没有在这里声称能自动抓取所有网盘材料、识别任意格式或运行提交的程序。

## 2. 把这次评审的标准固定下来

我不希望同一批作品因为提示词或评价标准悄悄变了而失去可比性。因此评分任务会绑定评价策略、rubric、Prompt、输入配置和响应格式的版本。

任务创建器根据权威输入配置核对版本，不一致就拒绝创建，并用配置指纹记录这次任务采用的口径。同一来源、同一配置的重复创建请求可以复用已有任务，避免重复建任务。

换 Provider 时也要保持评价标准、提示词、输入和返回格式一致。这个约束不能代替模型效果验证，但能避免把“更换调用服务”和“更改评价标准”混在一起。

## 3. 让 AI 先形成一份可检查的判断

AI 输出维度分和评语，界面把它们连同总分展示给评委。实际使用中，评委会直接复用其中的评语，并把分数作为重要参考。

系统保留每次评分尝试和结果快照，关联作品、任务和配置。重试创建新的尝试，成功记录继续保留；评分阶段完成时引用具体尝试，再进入复核阶段。这样后来的决定能指向一个确定版本。

公开演示的分数和评语是离线预置，不能据此判断真实模型的准确率或稳定性。[材料与评分界面](screenshots/materials.png)展示的是应用如何呈现这些信息。

## 4. 出问题时，先分清要补材料还是重新判断

失败、证据不足和需要人工复核，不能都算成“还没完成”。系统分别记录阶段、状态、错误和重试条件，通过复核工单承接人工处理。

强制复核会阻止自动采用。对于执行结果不明的请求，也不能直接发起覆盖性重试，以免把还没核清的结果丢掉。

我在界面为一个失败案例登记了“同模型重试”决定，但没有执行模型请求。另一个旧演示案例的状态不符合采用入口要求，系统拒绝了操作。这些情况都保留在[操作记录](REVIEW_EXAMPLE.md)，方便看清哪些步骤实际通过了、哪里还有限制。

## 5. 人工看过、采用和最终确认，是三件事

评委写下一条复核意见，不等于系统已经采用了那个结果。因此我把复核决定、结果采用和最终锁定分开保存。

采用时会检查决定类型、工单、任务状态以及结果绑定；最终锁定则明确已经确认的版本。后续再产生评分，也不能把人工确认悄悄替换掉。

演示里，我用同一个案例在界面创建采用决定、采用92分合成结果并新建锁定，随后通过工单服务完成结案。这里的分数是预置的，采用、锁定和结案是实际操作。

## 6. 输出前，确认还有没有未处理的事项

导出时不能只取“最新一个分数”。权威结果服务先找有效的人工最终锁定，没有锁定再找有效采用记录，同时检查对应快照和未结案的阻断工单。

同一个案例，我做了两次请求：

| 什么时候请求 | 系统怎样处理 |
|---|---|
| 已锁定，但阻断工单还没结案 | 拒绝输出，返回409 |
| 工单结案之后 | 返回200，采用人工最终锁定的92分结果 |

输出关联任务、条目、评分尝试、结果快照、采用和锁定记录，可以追溯这个结果怎样产生。推导结果时不调用模型，也不改写上游评分。

[最终原始响应](examples/authoritative-result.json) · [阻断原始响应](examples/unresolved-blocked.json)

Excel、Word和CSV现已接入相同的权威结果链路。在“结果导出”页选择任务和可导出条目；有未结案阻断工单的条目不能选中。直接请求整任务时，只要有一个条目不满足条件就返回409，不静默漏项。文件仅包含所选任务结果及其版本，不混入旧综合分。下载本身不会把任务生命周期自动推进为完成，因此演示任务仍可显示 export/pending。见[导出说明](EXPORTS.md)。

## 这些设计可以怎样复用

材料登记、标准版本、评分尝试、人工采用和最终确认，不只在作品评审中会遇到。我认为它们也可以作为其他材料审核任务的设计参考。

| 可以带走的方法 | 换到新业务时要重新确认 |
|---|---|
| 材料登记与输入校验 | 材料类型、必需证据、权限和隐私要求 |
| 标准版本与评分记录 | 评价规则、提示词、输出格式和模型效果 |
| 复核、采用与锁定 | 谁负责判断，什么时候必须复核，什么算最终确认 |
| 输出前的权威结果检查 | 下游接收什么字段，如何形成完整交付文件 |

当前系统面向单用户本机运行；这些是可迁移的设计经验，不代表已经完成其他行业或多用户部署验证。
